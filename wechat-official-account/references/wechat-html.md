# 微信公众号图文的 HTML 与草稿检查

## 来源与适用范围

[微信公众平台文章结构验证规范](https://github.com/wechatjs/verify-article-structure-spec/blob/main/verify_article_structure.md) 公开了第三方编辑器的结构、CSS、字体和深色模式规则。它给出典型触发条件和反例。完整平台标签和属性允许范围仍需通过当前导入入口及微信阅读端验证。[上游排版组件和检查器](https://github.com/isjiamu/gzh-design-skill/tree/750a50dffdc4abb5e853b98136dad13a57e64ce3) 则给出便于持续使用的保守子集。

| 场景 | 主题采用的写法 |
|---|---|
| 正文和卡片 | 单个 `section` 收纳正文。子 `section`、`p`、`h3` 承担块结构，`span`、`strong`、`em`、`br` 承担行内结构。把文字放入 `span[leaf]`，块元素留在叶子外。`section[nodeleaf]` 留给平台指定组件和图片。 |
| 基础样式 | 使用元素上的 `style`，常用颜色、字号、字重、行高、内外边距、细边框、圆角和浅色底。正文沿用编辑器默认字体。行高留足多行空间，宽度依容器伸缩。超过手机阅读区的表格拆为纵向字段。 |
| 代码 | 每行一个 `p`，以成对的不换行空格保留每级缩进。等宽样式限于代码，长行可换行。 |
| 图片 | 使用 `img` 和独立图注，按原比例缩放。上传正文图后在草稿读回中核对实际素材。把浏览器本地路径和 data URL 留给本地预览，公众号草稿使用平台上传后的图片资产。示意图提供文字图注。 |
| 链接 | 对公众号文章链接及其他合资格链接用后台预览核对点击结果。普通出处可保留为可辨认的文献名、编号或正文文字。 |
| 兼容风险 | 把 CSS 放在内联样式中，正文排除脚本、外部样式表、全局 class/id、表单和 iframe。主题优先用文档流和纯色背景，避开绝对定位、Grid、CSS 变量、字体覆盖、固定宽高与文字渐变。平台原生生成的富媒体和 SVG 有独立的规则。 |

## 视频号与读回

来自视频号的分享短链用来定位素材。在公众号图文编辑器通过「视频号」原生入口选择视频，把原生卡片插到正文首位，再保存和重新打开同一草稿。对照标题、作者和封面，核对卡片顺序以及正文图片。原生视频元数据来自平台创建的组件，通用 HTML 校验只处理正文主题。若当前草稿入口只接受正文 HTML，单独记下视频引用和插入位置，按实际结果记录原生组件状态。

本地先分别检查主题源、正文 HTML、窄屏预览。平台保存后再核对草稿箱标题、视频卡、实际图片、代码换行与深色模式。网页预览中的复制按钮属于包装层。
